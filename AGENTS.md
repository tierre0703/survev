# AGENTS.md

Guidance for AI coding agents working in this repository. For human-facing
docs see `README.md`, `HOSTING.md`, and `COMMIT_FORMAT.md`.

## Repository overview

Survev is an open-source recreation of the 2D top-down battle royale surviv.io.
It is a TypeScript/Node pnpm monorepo plus a native Android port of the client.

| Path | What it is |
|---|---|
| `shared/` | Code used by both server and client: binary net protocol (`lib/bitBuffer.ts`, `net/`), math/collision/terrain utils (`utils/`), game/map/object defs (`defs/`), `gameConfig.ts`. |
| `server/` | API (`src/api/`) + game server (`src/gameServer.ts`) on Hono, Drizzle/Postgres, optional Redis. |
| `client/` | Web client: Vite + TypeScript + PIXI.js-legacy + jQuery/Bootstrap/EJS UI. |
| `client-mobile/` | Native **C++17 / axmol** port of `client` for Android. Contains the C++ game code, host tests, codegen tools, and Android build scripts. |
| `bot/`, `tests/` | Bot harness and vitest test suites. |
| `tools/` | Repo-level tooling. |

`shared/defs` is the **single source of truth** for game data. The C++ port under
`client-mobile/src/render/GeneratedDefs.cpp`, `client-mobile/src/net/generatedDefs.inc`,
and the audio tables are **generated** from it — never hand-edit generated files.

## Setup

Requires Node `>=22.18.0` and pnpm `11.24.0`.

```sh
pnpm install        # or: pnpm survev-setup
```

The game server needs Postgres (`:5432`) and Redis (`:6379`); both are optional
to run but required for accounts/caching. See `README.md` for DB/Redis setup.

## Common commands

```sh
pnpm dev:client     # Vite dev server (web client)
pnpm dev:server     # API :8000 + game server :9001
pnpm dev            # all three concurrently
pnpm build          # server build then client build
pnpm lint           # oxlint --fix + dprint fmt
pnpm lint:ci        # oxlint + dprint check (what CI runs)
pnpm --filter @survev/tests test   # vitest suite in tests/
```

Game server details (`server/`): `dev:api`, `dev:game`, `db:generate`,
`db:migrate`, `db:studio`, `db:seed`, `db:wipe`, `stressTest`, `typecheck`.

## Lint & formatting

- Formatting is enforced with **dprint** (`dprint.json`, 4-space indent for TS,
  line width 120) and linted with **oxlint** (`.oxlintrc.json`).
- Run `pnpm lint` before committing, or `pnpm lint:ci` to check without writing.
- Never format `*.svg` (excluded) or lockfiles. Don't mass-reformat files you
  aren't otherwise changing.

## Commit conventions

Follow `COMMIT_FORMAT.md` exactly:

```
<type> (<scope>): (<file>) <subject>
```

- `type` is one of `chore`, `deploy`, `docs`, `enhance`, `feat`, `fix`, `perf`,
  `refactor`, `style` (combine with `+`).
- `scope` and `file` are optional; `file` is a repo-relative path.
- Subject: imperative, present tense, no trailing period, not capitalized,
  max 100 characters per line.

## Testing

- **Web/shared/server:** `pnpm --filter @survev/tests test` runs vitest suites in
  `tests/` (maps, objects, net, quests, svgs, ...). Prefer adding/adjusting a
  test when changing `shared/` behavior.
- **Native port:** `client-mobile/tests/` is an engine-independent CMake host
  test binary, `surv_tests`. Build with MSVC on Windows:
  ```powershell
  cd client-mobile
  . .\tools\android-env.ps1
  cmake -S tests -B build-tests -G "Visual Studio 17 2022" -A x64
  cmake --build build-tests --config Release
  .\build-tests\Release\surv_tests.exe
  ```
  It must stay green (it currently asserts zero failures). Several fixtures in
  `client-mobile/tests/ReferenceData.h` are generated by running the real TS code
  (`node tools/gen_reference.mjs`), so the C++ port is checked bit-for-bit
  against `shared/` and `client/` sources.

## Native Android port (`client-mobile/`)

Read `client-mobile/plan.md` first — it maps every web module to its C++ target,
lists milestones M0–M9, and records per-milestone implementation status. Also see
`client-mobile/BUILDING.md` (build), `client-mobile/M4_REMAINING.md` (render
status) and `client-mobile/M6_AUDIO.md` (audio status).

### Build & test workflow (Windows, PowerShell)

Environment must be dot-sourced first (sets Android SDK/NDK, JDK, and the SDK's
CMake 3.22.1 + ninja):

```powershell
cd client-mobile
. .\tools\android-env.ps1

# Native libs, one build dir per ABI (first build compiles the whole engine)
.\tools\build-native.ps1 -Abis "arm64-v8a"   # device / Houdini emulator
.\tools\build-native.ps1 -Abis "x86_64"      # native emulator (best crash stacks)

# APK (Gradle-free: aapt2/javac/d8/zipalign/apksigner)
.\tools\build-apk.ps1 -Abis "x86_64"         # -> SurvevMobile-debug.apk
```

Install / run / inspect:

```powershell
$adb = Join-Path $env:ANDROID_HOME 'platform-tools\adb.exe'
& $adb install -r .\SurvevMobile-debug.apk
& $adb shell am force-stop com.survev.mobile
& $adb logcat -c
& $adb shell am start -n com.survev.mobile/dev.axmol.app.AppActivity
& $adb logcat -d -v brief
& $adb logcat -b crash -d -v brief        # native crash backtraces
```

Point the emulator at a dev server without config changes:
`& $adb reverse tcp:8000 tcp:8000` and `& $adb reverse tcp:9000 tcp:9000`
(the API is `:8000`, game `:9000+`; `DevConfig.h` uses `http://127.0.0.1:8000`).
Join tokens are single-use and expire in 10s, so always use the
`/api/find_game_v2` discovery path.

### Codegen (regenerate after changing `shared/defs` or web sources)

Always run from `client-mobile/` with Node's type stripping:

```sh
node --experimental-transform-types tools/codegen_defs.mjs src/net/generatedDefs.inc
node --experimental-transform-types tools/codegen_render_defs.mjs   # -> src/render/GeneratedDefs.cpp
node --experimental-transform-types tools/codegen_sound_defs.mjs    # -> src/audio/GeneratedSoundDefs.cpp
node tools/gen_reference.mjs                                        # tests/ReferenceData.h fixtures
node tools/build-atlas.mjs --res low                                # sprite atlases -> Content/atlas
```

`Content/` is gitignored; run `build-atlas.mjs` before packaging an APK. Generated
files are deterministic — commit them, but only via the tools above.

### Architecture conventions

- **Adapter layer:** the ported draw code targets `src/render/PixiLike.h` (a
  minimal PIXI surface), not axmol directly. `AxmolPixi.h` is the real engine
  implementation; `NullPixi.h` is the headless recording implementation used by
  host tests. New engine APIs must be added to `PixiLike.h` **and both**
  implementations.
- **Keep ports diffable:** logic should mirror the original TS (`shared/`,
  `client/src/objects/*`, `client/src/map.ts`, `renderer.ts`, `camera.ts`, ...)
  closely; only draw calls should differ. Reference the TS file in a comment.
- **Object model:** `src/game/objects/GameObject.h` ports `objectPool.ts`
  (`AbstractObject`, `Pool<T>`, `ObjectCreator`); barns live in `Barns.{h,cpp}`,
  player skeletal rendering in `PlayerRender.cpp`, the render context (`Ctx`,
  i.e. web `Game`) in `GameWorld.{h,cpp}`.
- **Defs:** extend `src/render/Defs.h` structs and the codegen
  (`tools/codegen_render_defs.mjs`) together, then regenerate.
- **Do not regress** the critical fixes recorded in `M4_REMAINING.md` §1
  (node ownership/reparenting, convex-fan `drawSolidPoly`, clamped layer index,
  axslc shader packaging).

### Gotchas

- `axmol/` and `Content/` are vendored/staged and gitignored (large); they live
  on disk. `tools/vendor-axmol.ps1` and `tools/sync-content.ps1` recreate them.
- The **arm64** emulator runs under Houdini ARM translation, so backtraces are
  useless — build/install the **x86_64** APK for real crash stacks.
- `build-apk.ps1` must keep packaging `assets/axslc/**` (missing it causes a
  black screen) and storing `resources.arsc` uncompressed + aligned.
- Gradle cannot run while the Astrill VPN LSP is active; use the Gradle-free APK
  script (see `BUILDING.md` "Why not Gradle?").

## Working in this repo

- Treat unfamiliar or modified files as potential user work; investigate before
  deleting or overwriting. `client-mobile/Content/` and generated `*.inc`/tables
  are often machine-produced — regenerate rather than hand-edit.
- Match the surrounding style and structure. Keep changes scoped; avoid
  drive-by reformatting (dprint may do it for you via `pnpm lint`).
- Update the relevant status doc (`client-mobile/plan.md`, `M4_REMAINING.md`,
  `M6_AUDIO.md`) when you change ported behavior, and keep `surv_tests` green.
